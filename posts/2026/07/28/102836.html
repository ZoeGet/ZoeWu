前言

使用 Git 管理项目时，经常会遇到下面这些情况：

  • 文件改错了，还没有执行 git add；
  • 文件已经加入暂存区，但是不想提交；
  • 本地已经提交，希望撤销最近一次提交；
  • 错误提交已经推送到 GitHub；
  • 希望把整个分支恢复到某个历史版本；
  • 执行 reset 后才发现回退错了。

这些操作都可以叫作“回滚”，但不同场景使用的命令并不一样。

四、撤销最近一次本地提交

如果提交还没有推送到 GitHub，可以使用 git reset。

1. 撤销提交，保留暂存状态

执行后：

  • 最近一次提交被撤销；
  • 文件修改仍然保留；
  • 修改仍然位于暂存区；
  • 可以修改后重新提交。

适合提交信息写错，或者发现还少提交了一个文件的情况。

七、使用 reset 回滚已经推送的版本

如果是自己的个人分支，并且确认没有其他人基于这些提交继续开发，也可以重写远程历史。

先把本地分支回退到目标版本：

然后更新 GitHub 远程分支：

这里推荐使用 --force-with-lease，不要直接使用 --force。

--force-with-lease 会检查远程分支是否出现了本地不知道的新提交。如果远程分支已经被别人更新，推送会被拒绝，从而避免直接覆盖别人的工作。

这种方法的效果是：

  • GitHub 分支指针退回到旧提交；
  • 目标提交之后的提交不再出现在正常分支历史中；
  • 已经拉取过旧历史的其他成员可能出现分支冲突；
  • 受保护分支可能禁止强制推送。

因此，下列分支不建议使用这种方式：

  • 多人协作的 main 或 master；
  • 已经发布给其他人使用的分支；
  • 开启分支保护规则的分支；
  • 无法确认远程是否有新提交的分支。
